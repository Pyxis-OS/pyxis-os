# RTL8111 Ethernet driver

Caelum supports the ThinkPad's built-in RTL8168h/8111h, identified by
TxConfig XID `541`. The existing remote terminal works through this port in
VFIO/QEMU and on the owner's native cold/PXE boot with the dock attached.
[Qualification results](../development/rtl8111-qualification.md) distinguish
agent measurements from owner observations. The dock-facing onboard XID `502`
is diagnosed as unsupported; its presence does not prevent the built-in port
from working.

## Selection and machine configuration

An RTL8168h/8111h is one supported Ethernet controller within the retained
[interface model](network-interfaces.md); the stock automatic wired policy gives it
an `ethN` name by ascending boot-local controller ID, with its own optional DHCP
client ([interface selection](net0-selection.md)). An explicit entry in the
[boot network profile](networking.md#boot-configuration-and-use) chooses a
controller with `select = "link"`, `driver = "virtio"` or a private
`mac = "..."`; a MAC selector must match one supported controller uniquely. Route,
DNS and management selections name interfaces explicitly (the stock profile pins
them to `eth0`), and there is no automatic fallback or controller switching.

A controller's first successful binding lasts until reboot. Reapplying
configuration to that interface is allowed; clearing removes only IPv4 settings.
Missing or ambiguous selection preserves the existing binding. Discovery and DMA
state belong to each controller independently.

Addresses come from DHCP by default or from a static `address`, `prefix` and
`gateway` in a private profile; these are machine settings, not kernel defaults.
Package a private profile containing the owner's MAC through
[`NETWORK_CONFIG`](../development/configuration.md#image-network-profile):

```sh
make -j16 image NETWORK_CONFIG=/private/network.lua
```

Set `CROSS_COMPILE` to the installed toolchain prefix if it is outside `PATH`.
Use the same profile for native/PXE ELF and initrd assembly. Keep hardware MAC
bytes outside version control and published captures.
[ThinkPad passthrough](../development/thinkpad-nic-passthrough.md)
records the host setup and launcher options.

## Ownership and limits

Preparation identifies the variant before variant-specific writes, obtains
exclusive PCI/MMIO ownership, confirms halt/reset, and initializes the PHY
without importing firmware. Each supported controller retains independent
32-entry RX/TX rings with fixed 2048-byte buffers and a page for tally snapshots.
Controllers not bound to an interface keep DMA and delivery disabled; each bound
controller is activated and serviced by the BSP network worker.

Carrier loss suspends pending TX completion deadlines without returning device
ownership. Carrier return grants pending descriptors a fresh five seconds and
kicks the queue. A stall with carrier up or another runtime failure stops the
controller until reboot; buffers and claims remain retained. The
[hardware profile](rtl8111-hardware.md#ethernet-io) records the register,
completion, reset and [debugger tally](rtl8111-hardware.md#hardware-counter-inspection)
contracts.

Only XID `541` is supported. Jumbo-frame reassembly, offloads and automatic
restart are absent. Native unplug and device-owned TX during carrier loss
remain unobserved. The qualified traffic does not establish gigabit line rate,
every PHY speed or every firmware/power handoff. Deferred work and revisit
conditions belong to [technical debt](https://git.internal/PyxisOS/pyxis-os/issues/1432).
