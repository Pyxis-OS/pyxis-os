# Installed Limine menu allowlist qualification

The old installer copied every live-menu entry except Install Pyxis. The fixed
builder emits only normal/rescue entries, timeout 3 and the selected disk binding;
its generated bytes remain part of plan fingerprinting and ESP verification.
No disk-authority, consent, formatting or publication-order change.

## Inputs and method

Source base `8395f988`, userland base `220b8076`; fixed userland `64e22a05`.
Local target installer and full image builds pass with the existing e0801c2
compiler and verified unchanged df87791 SDK/ports artifacts (exact-main CI API
run 2578, main `ba5e134d`). SDK source inputs and ABI are unchanged by this fix.
The parent CI independently builds with df87791. No compiler rebuild.

Interactive Q35/nested KVM/host CPU, four CPUs, 1 GiB, OVMF, modern VirtIO block,
`cache=none`, no NIC/USB. Each target is a disposable blank 2 GiB image.
Boot `init=boot://init-install.pxe boot.install=1`, choose Install → Read the
room, accept the displayed journal and Review, then explicitly confirm `wipe`.
Update uses its own Review and `update` confirmation. No real ESP writes.
These are functional checks; no timing or throughput comparison is claimed.

## Results

- Old-generator Install, kernel `ba5e134d`, completes all verification and reports
  `installed`. Host `mtype` of its ESP finds seven entries, including the five FAT
  tools and four `boot.install=1` command lines.
- The same kernel and archive, changing only `installer.pxe` and removing the
  unused template asset, successfully Update that installation. Admission treats
  the extra command lines as rebuildable ESP configuration damage, as before.
  It reports `updated` after program/ESP verification. Extracted menu has exactly
  normal/rescue, timeout 3 and both bindings matching the retained GPT disk GUID.
  The before/after `boot/revision` bytes are identical (`ba5e134d054f`).
- Fresh fixed full-image Install, kernel `8395f988`, reports `installed` after
  verification. Its menu has the same two-entry structure, timeout and correctly
  bound normal/rescue command lines. The extracted fresh and updated menus agree
  byte-for-byte after substituting their different scratch GUIDs.
- Neither fixed menu contains `boot.install`, FAT tool entries, Install Pyxis or
  a global `default_entry`. The live menu still includes its original tools.

Raw images, extracted configurations, revision records, screenshots, serial
logs and image/binary SHA-256 records are private under
`/shared/present/installed-menu-allowlist/`. All installer QEMU jobs stopped.
